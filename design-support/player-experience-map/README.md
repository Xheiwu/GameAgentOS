# Player Experience Map

## Purpose

A thinking framework for agents to analyze the intended player feeling before selecting systems.

This layer does not define a game template. It helps translate player experience goals into possible design directions.

## Core Questions

1. What should the player feel?
2. What player behavior creates that feeling?
3. What feedback reinforces that behavior?
4. What systems could support this experience?

## Experience Dimensions

### Emotion
Examples:
- power
- discovery
- tension
- mastery
- creativity

### Player Action
Examples:
- fight
- explore
- build
- collect
- solve
- manage

### Feedback
Examples:
- visual impact
- progression
- new options
- narrative consequence

### Motivation
Examples:
- curiosity
- achievement
- optimization
- expression

## Usage

Agents should use this framework before jumping into implementation details.

The goal is not to decide the design, but to provide a structured way to reason about player experience.
